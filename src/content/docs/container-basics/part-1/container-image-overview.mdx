## イメージの種類と具体例
### OSのみのイメージ
アプリケーションを動かすための土台となる、OSだけが導入されたイメージ。
実行環境を自由に作成したい場合に利用する。

- `alpine` (Alpine Linux):  
  容量がわずか数MBと超軽量かつ、セキュリティ的な安全性が高いLinuxディストリビューション。
  コンテナのサイズを最小限に抑えたい場合によく利用される。
- `ubuntu` / `debian`:  
  汎用的なLinuxディストリビューション。
  よく使われるライブラリは導入済みのほか、パッケージマネージャを用いて追加のパッケージを導入することも容易である。
  開発時や複雑な環境を構築する必要がある場合によく利用される。
- `amazonlinux`:  
  AWS環境（EC2）などと同様の動作環境を構築したい場合に利用される。

### 言語ランタイム・ミドルウェアが導入済みのイメージ
OSの上に、プログラミング言語の実行環境やミドルウェアが既にインストールされたイメージ。
開発者が自分のソースコードや設定ファイルを乗せるだけで動かすことができる。

- 言語ランタイム等
  - `python` / `node` / `ruby` / `golang`:  
    各言語の実行環境（インタプリタやコンパイラ）と、パッケージマネージャ（pip, npmなど）が導入済み。
  - `eclipse-temurin` / `amazoncorretto` (Java)  
    Javaを実行するためのJDK/JREが含まれる。
- Webサーバー
  - `nginx` / `httpd` (Apache):  
    Webサーバーとしてチューニング済み。
- データベース（データストア）
  - `mysql` / `postgres` / `redis` / `mongo`:  
    起動時にパスワードなどの環境変数を渡すことで、データベース等を立ち上げられる。

### アプリケーション導入済みのイメージ
OS、ミドルウェア、アプリケーションがすべて含まれるため、起動するだけですぐにサービスとして利用可能。

- `wordpress`:  
  PHP環境やWordPress本体が設定済みのイメージ。別途MySQLコンテナを起動し接続するだけで、ブログやサイトとして立ち上げることができる。
- `nextcloud`:
  セルフホスト型のオンラインストレージ。
- `jenkins` / `gitlab-ce`:  
  CI/CDツールやソースコード管理ツールが導入済みのイメージ。社内用の開発インフラを簡単に立ち上げることができる。

## イメージとタグ
レジストリにおいて、同じイメージの異なるバージョンを識別するために利用されるのがタグである。

### 最新版指定タグ（`latest`）
例: `ubuntu:latest`, `nginx:latest`

多くの場合、最新の安定版を指すタグ。タグを何も指定しなかった場合にもデフォルトで選ばれる。
最新版を手軽に利用することができる一方、
イメージの `pull` を行うタイミングによって中身のバージョンが変わることがある。
互換性やセキュリティの問題が発生しうることから、本番環境では避けるのが一般的。

### バージョン指定タグ
意図しないアップデートを防ぎ、環境を固定する場合に最もよく利用される。

#### メジャー・マイナーバージョン
例: `node:18`, `python:3.11`, `postgres:15`

仕様変更によるシステムが動作しなくなることは防ぎ（互換性を保ち）、
セキュリティパッチ等は受け入れたい場合に利用する。

#### パッチバージョン
例: `mysql:8.0.33`, `golang:1.20.5`

パッチバージョンまで完全に固定する。
本番環境等で、検証環境と全く同じものを動作させたい場合に利用する。

### ベースOSや軽量化を示すタグ（サフィックス）
同じバージョンの言語やアプリに対して、ベースOSが複数用意されている場合に、
それらを区別するためにつける。一般的にはバージョン等の後ろにハイフン（`-`）で繋いで表現されることが多い。

#### `-alphine`
例: `node:18-alpine`, `nginx:1.25-alpine`

軽量なAlpine Linuxをベースとしたイメージ。
イメージサイズ及び消費リソースが小さく、セキュリティの攻撃対象となる領域（アタックサーフェス）を減らすことができる。

#### `-slim`
例: `python:3.11-slim`, `debian:trixie-slim`

標準的なOSから、マニュアルやパッケージを削った軽量版。
Alphine Linuxの互換性問題を避けつつ、サイズを小さくしたい場合によく選ばれる。

#### OSのコードネーム
例: `ruby:3.2-bullseye`, `ubuntu:jammy`

特定のOSバージョンに依存するパッケージを利用したい場合に指定する。
`bullseye`, `bookworm` はDebianのバージョン、 `jammy` はUbuntuのバージョンを指している。
