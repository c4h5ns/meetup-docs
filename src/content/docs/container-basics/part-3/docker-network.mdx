Dockerコンテナは、プロセスやファイルシステム同様、デフォルトではホストOSのネットワークと隔離されている。
一方でサービスを公開する場合や、複数のコンテナを連携させる場合には、コンテナ同士の通信が必要になる。
Dockerでは、コンテナ同士の通信を実現するために、コンテナをネットワークに接続する仕組みが用意されている。


## ネットワークの隔離（Network Namespaces）
ネットワークの隔離は、LinuxのNetwork Namespacesという機能を利用して実現されている。
コンテナを起動すると、ホストOSとは別のネットワーク空間が作成され、コンテナはその中で独自のネットワークスタックを持つことになる。
コンテナの中からは、専用の仮想ネットワークインターフェース（`eth0` など）が見え、ホストOSのネットワークインターフェースは見えない。

## ネットワークモードの種類とポート割り当て
コンテナをネットワークに接続する方法として、主に3種類のネットワークモードが用意されている。

### `bridge` モード（デフォルト）
- Dockerが作成する仮想ブリッジネットワーク（`docker0`）に接続
- `docker run -p 8080:80` のようにポートを割り当てることで、ホストOSのポートとコンテナのポートを接続できる（ポートマッピング）

### `host` モード
- ホストOSのネットワークスタックをそのまま利用する
- コンテナの中からは、ホストOSのネットワークインターフェースが見える
- ポートマッピングは不要で、コンテナのポートはそのままホストOSのポートとして利用できる（コンテナのポートが8080の場合、ホストOSの8080ポートでアクセス可能）

### `none` モード
- ネットワークを無効化する
- ループバックインターフェース（`lo`）のみが利用可能で、外部との通信はできない

以降では、デフォルトの `bridge` モードを前提として説明する。

## ネットワークと名前解決
### Bridgeネットワーク `docker0` とIPアドレスの割り当て
Dockerが作成する仮想ブリッジネットワーク（`docker0`）は、ホストの物理ネットワーク（社内LANやインターネット）とは被らない、
専用のプライベートサブネット（`172.17.0.0/16`）を持つ。
コンテナを起動すると、デフォルトでは `docker0` に接続される。
その際にDockerのDHCPのような仕組みにより、 `docker0` のサブネット内のIPアドレス（`172.17.0.2`, `172.17.0.3`, ...）が自動的に割り当てられる。

### ネットワークの作成とコンテナ間通信
現時点で、すでに複数のコンテナが起動している場合、コンテナ同士は `docker0` に接続されているため、IPアドレスを指定することで通信できるが、
以下のような問題がある。

- コンテナのIPアドレスは自動割り当てされるため、コンテナを再起動するとIPアドレスが変わる可能性がある
- すべてのコンテナが同じネットワークに接続されているため、意図しないコンテナ同士の通信が発生する可能性があり、セキュリティ上の懸念がある

この対策として、ネットワークを作成する方法がある。
ネットワークを作成すると、 `docker0` とは別の仮想ブリッジネットワークと専用の重複しないサブネットが作成される。
同ネットワーク内のコンテナ同士は、コンテナ名を指定することでDNSのように名前解決され、IPアドレスを意識せずに通信できるようになる。
一方、異なるネットワーク間の通信はLinuxの `iptables` により遮断されるため、意図しないコンテナ同士の通信を防ぐことができる。

- <code>docker network create [<i>options...</i>] <i>network-name</i></code>  
  新しいネットワークを作成する
- <code>\-\-subnet <i>subnet</i></code>  
作成するネットワークのサブネットを指定する（例: `--subnet 10.5.0.0/16`）


- <code>docker run \-\-network <i>network-name</i> [<i>options...</i>] <i>image</i></code>  
  コンテナの起動時にネットワークを指定する

```sh
docker network create my-app-nw

# コンテナの起動時にネットワークを指定する
docker run -d --network my-app-nw image1
docker run -d --network my-app-nw image2
```
